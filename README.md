# AI 求职准备助手

面向首次准备实习大学生的 Desktop Web 演示原型。

产品聚焦一个核心问题：

> **基于我当前真实经历和目标岗位，我下一步最应该补什么？**

当前版本已实现从目标岗位与经历输入、AI 理解确认、用户纠错、岗位差距诊断、下一步行动选择、行动执行、行动反馈到诊断更新的一轮完整闭环。

本项目使用 **林浩（虚构模拟案例）** 作为标准演示案例，用于稳定展示完整流程。部分 AI 输出、异常状态和时间推进采用受控 Mock，不代表已接入真实 AI 服务或真实业务数据。

---

## 产品形态

- 形态：Desktop Web
- 主要演示尺寸：1440 × 900
- 主要使用角色：首次准备实习、已有明确目标岗位的大学生
- 核心导航：首页 / 我的诊断 / 当前行动
- 演示案例：林浩（虚构模拟案例）

---

## 技术栈

- React
- TypeScript
- Vite
- lucide-react
- Nginx（Docker 生产静态部署）

当前版本为前端演示原型：

- 无后端服务；
- 无数据库；
- 无真实 AI API；
- 业务数据与 AI 结果使用 Mock 数据驱动；
- 导航使用浏览器 hash 路由；
- 当前演示状态仅在当前浏览器会话中保存。

## 标准演示流程

建议评审优先使用 **林浩标准模拟案例** 体验完整闭环。

完整流程为：

```text
P01 首页
→ P02 建立诊断
→ AI 分析处理中
→ P03 AI 理解确认
→ 补充 / 确认 / 纠正
→ 重新分析
→ P04 我的诊断
→ P05 行动选择
→ P06 当前行动
→ 周期结束
→ P07 行动反馈
→ 反馈更新处理中
→ P08 本次更新结果
→ 查看最新诊断 / 返回首页 / 规划下一轮
```

标准案例中，用户会经历一次 AI 初始理解偏高、用户纠正、建议重新排序、执行 Java 核心基础行动、提交真实行动反馈、系统更新最新诊断的过程。

## 演示模式

左下角提供 **“演示模式”**，用于评审快速查看不适合在短时间内自然等待或随机触发的状态。

可用于查看或切换：

- 首次使用；
- 已有记录；
- 信息不足；
- 模拟 AI 生成失败；
- 初步诊断；
- 用户纠正后的诊断；
- 行动进行中；
- 行动反馈完成后的状态；
- 最新诊断。

当存在正在进行的可执行行动时，演示模式中还会出现：

> **快进到本周期结束**

该操作只用于模拟真实时间流逝，不会自动提交行动反馈，也不会直接修改用户能力状态。

演示模式属于本次原型评审辅助工具，不属于正常用户核心业务功能。

## 当前已实现

### 1. 首页与诊断建立

- 首次使用状态；
- 已有诊断记录状态；
- 自定义岗位与经历输入；
- 林浩模拟案例预填；
- 标准演示路径；
- 输入校验；
- 无 JD 时的初步诊断提示。

### 2. AI 理解确认

- 已确认事实 `Confirmed`；
- AI 推测 `Inferred`；
- 待确认信息 `Unknown`；
- 用户补充信息；
- 已补充信息再次修改；
- AI 推测确认与撤销；
- “不准确”纠错；
- 纠正后重新分析。

核心规则：

> **未提及 ≠ 不会。**

系统不会仅因为用户没有提到某项能力，就直接认定为缺口。

### 3. 岗位差距诊断

支持以下能力状态：

- `met`：当前证据支持已经具备；
- `partial`：部分具备；
- `gap`：当前证据明确支持存在缺口；
- `unknown`：信息不足，不能判断。

支持优先级：

- P0：当前优先解决；
- P1：下一阶段补充；
- P2：后续增强。

同时支持：

- 初步诊断；
- 正式诊断；
- 建议依据 Drawer；
- 建议变化 Diff；
- 未确认信息提示；
- 信息不足时“不生成可靠排序”；
- 变化记录；
- 行动反馈后的最新诊断。

### 4. 行动选择

当前原型区分两类建议：

#### 可执行行动

已经配置完整行动内容、完成标准和反馈映射的建议，可以进入“当前行动”。

标准演示中，Java 核心基础为完整可执行案例。

#### Direction

如果当前只能够可靠判断“下一阶段方向”，但尚未配置完整、可验证的行动任务，系统不会伪造计划。

此时会：

- 明确本次诊断已经完成；
- 展示当前方向与优先级；
- 允许返回查看诊断结果；
- 提供“体验完整模拟闭环”，载入标准案例。

### 5. 当前行动

已实现：

- 行动进行中；
- 行动目标；
- 任务与完成标准；
- 行动依据；
- 调整当前行动；
- 周期结束；
- 演示模式时间快进。

进度仅表示真实任务完成数量，不使用“掌握度 60%”一类伪精确能力评分。

### 6. 行动反馈

支持反馈：

- Java 多线程学习情况；
- MySQL 索引学习情况；
- 算法题实际完成数量；
- 独立完成数量；
- 当前主要困难。

同时包含基础输入校验，例如独立完成数量不能超过实际完成数量。

行动反馈会作为新的用户事实进入下一轮诊断。

### 7. 行动后的诊断更新

完成行动反馈后，系统会展示：

- 新增的已确认事实；
- 差距状态变化；
- 前后 Diff；
- 下一阶段建议；
- 本轮闭环完成状态。

标准案例中可看到：

- Java 核心基础：`gap → partial`
- MySQL：仍为 `partial`，但新增索引学习事实
- Spring Boot：成为下一阶段主线
- Java 多线程与算法继续作为巩固项

### 8. 失败与边界状态

已实现：

- AI 分析处理中；
- 模拟 AI 生成失败；
- 重试；
- 返回修改；
- 信息不足；
- 无可靠建议排序；
- 纠正后重新分析；
- 行动反馈更新处理中；
- 完成弹窗。

AI 生成失败为受控 Mock 状态，用于验证失败后的信息保留、重试和返回修改流程。
