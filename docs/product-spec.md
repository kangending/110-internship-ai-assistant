# 产品需求说明（已确认内容）

## 项目名称

面向首次准备实习大学生的 AI 求职准备助手（暂定）

## 核心用户问题

首次准备实习的大学生已经有目标岗位，但不知道自己的经历与岗位要求之间还缺什么，也不知道下一步最应该做什么。

## 产品核心价值

帮助用户确认 AI 是否正确理解现状、识别与目标岗位之间的关键差距、理解建议依据、纠正错误理解、选择当前最值得做的行动，并在行动后根据新情况重新判断下一步。

## 产品核心闭环

目标岗位 → 用户现状 → AI 理解确认 → 差距诊断 → 用户纠正 → 建议重新排序 → 选择当前行动 → 行动反馈 → 更新差距与下一步建议。

## 统一模拟案例

**林浩是为验证产品流程构造的虚构测试角色，仅用于产品演示。**他的身份、经历、技能、岗位信息及后续行为均为模拟内容，不代表真实访谈、用户反馈或调研结果。本案例中的目标 JD 也是模拟信息，不对应真实招聘职位。“普通一本院校”可作为人物背景，但不参与技能差距判断，也不作为推荐优先级依据。

- 用户：林浩
- 年级：大三上学期
- 专业：软件工程
- 目标岗位：Java 后端开发实习生
- 计划：4 个月后开始投递
- 每周可投入时间：约 20 小时
- 初始描述：学过 Java 基础，有一个 Java + MySQL 学生管理系统
- AI 第一次误判：把“学过 Java 基础”理解成已经具备进入 Spring Boot 阶段的完整基础
- 用户纠正：实际刚学完集合，多线程不会，MySQL 只会 CRUD，项目只是 JDBC 课程作业
- 修正后的优先级：Java 核心基础 → MySQL 基础 → Spring Boot
- 后续：用户选择一个 7 天行动，完成后回来反馈，系统根据新事实重新调整建议

## 目标用户

首次正式准备技术类实习、已经明确目标岗位，却无法判断自身经历与岗位要求之间差距的大学生。本次聚焦大三上学期的软件工程学生：第一次正式准备实习，目标为 Java 后端开发实习生；已有一定 Java / MySQL 学习经历和一个课程项目，但尚未形成完整的 Java 后端岗位能力；计划约 4 个月后投递，每周可投入约 20 小时。

## 目标用户与案例选择依据

1. **大三上学期**：产品处理的是已有目标岗位后“现在优先补什么”，不是职业方向探索。大一、大二通常离投递较远，方向探索问题更突出；大三已积累一定课程、技能和项目经历并进入实习准备窗口，更容易出现“学过不少内容，却不知道哪些真正影响当前准备”的问题。
2. **软件工程专业**：本次不处理职业兴趣探索、转行或跨专业选择。该专业配合 Java 后端目标，可把流程集中在已有经历理解、岗位要求对照、差距判断和行动优先级。
3. **已有基础但不成熟**：完全零基础时下一步通常是从基础开始，差距诊断价值较弱；已有完整项目或正式实习经历的成熟用户更可能需要简历、投递和面试准备，超出本次范围。中间阶段用户已有积累，却难以判断当前优先级。
4. **4 个月后投递**：若还有一年以上，取舍不够迫切；若只剩一两周，则更可能进入简历、投递和面试冲刺。4 个月仍可改善能力，但无法补完所有 Java 后端知识，因此需要排序。
5. **每周约 20 小时**：有一定准备时间，却无法同时完成 Java、MySQL、Spring Boot、Redis、算法、JVM、计网等所有任务。时间约束让“当前优先做什么”成为真实决策。
6. **Java 后端演示岗位**：其要求可拆为 Java 基础、集合 / 多线程、Spring Boot、MyBatis、MySQL、Redis、Git / Linux、数据结构与算法和后端项目经历，适合验证“岗位要求 → 用户经历 → 已满足 / 部分满足 / 缺口 / 未知 → 优先行动”的流程。这是演示逻辑的选择，不是岗位热度的调研结论。

## 首次输入信息

首次建立岗位差距诊断时，使用少量结构化信息、自然语言经历描述和后续 AI 整理确认；不以大量技能勾选为主要输入方式。

- **目标岗位**：必填，例如 Java 后端开发实习生。
- **目标 JD**：建议填写，但不是强制。用户提供真实目标 JD 时，岗位要求优先依据该 JD，来源标记为 `jd`。没有具体 JD 时仍可继续，但需标记“基于通用岗位要求的初步诊断”；此类要求来源为 `generic_role_assumption`，不可冒充用户提供的 JD。
- **距离计划投递的时间**：例如 4 个月。
- **每周可投入准备时间**：例如 20 小时。
- **年级与专业**：例如大三上学期、软件工程。
- **当前经历自然语言描述**：可包含已学技能、课程、项目、实习、比赛和自认为薄弱的地方。

## AI 信息状态与判断规则

| 状态 | 含义 | 示例与边界 |
| --- | --- | --- |
| `confirmed` | 用户明确提供或确认的事实 | “学过 Java 基础”只能记录为已学习，不能升级为“基础扎实”。 |
| `inferred` | AI 根据事实做出、用户尚未确认的推测 | “可能已具备学习 Spring Boot 的基础”须允许用户确认或纠正。 |
| `unknown` | 目前信息不足，无法判断 | 没提 Redis 应记录“Redis 使用情况未知”，不能记录“不会 Redis”。 |

只有用户明确表达或明确确认的内容才是事实。未提及不等于不会；AI 推测不得与事实混用。用户最新明确纠正优先于冲突的 AI 推测，数据应保留旧推测与新纠正的关联，以支持后续展示修改前后；本轮不实现 Diff 页面。若缺失的关键信息会显著影响 Top 3 建议，应先请求补充，而不是直接给确定结论。

## 信息来源

| Source | 含义 |
| --- | --- |
| `user_input` | 用户首次填写或主动提供的信息 |
| `jd` | 用户提供的真实目标岗位 JD；模拟案例里的 JD 也仅为虚构的“用户提供 JD” |
| `ai_inference` | AI 根据已有信息做出的推测 |
| `generic_role_assumption` | 无具体 JD 时，基于岗位名称的通用岗位假设，必须明确为系统假设 |
| `user_correction` | 用户后续主动纠正或补充的信息，冲突时优先于 `ai_inference` |

`unknown` 表示没有足够信息，并非来自用户、JD 或推测，因此在数据中来源为 `null`。

## 差距状态与优先级

差距只分为：`met`（现有信息支持已满足要求）、`partial`（部分满足但与目标 JD 仍有明显差距）、`gap`（用户已明确确认存在缺口）、`unknown`（信息不足，无法判断）。不使用精确能力分数或岗位匹配百分比。

优先级只分为：`P0`（现在优先处理，典型情况为 JD 明确要求、用户已确认明显差距且是后续学习或项目的关键基础）、`P1`（接下来需要补，但当前不必最先处理）、`P2`（后续增强项，非当前主线必要前置）。本轮不实现复杂评分算法。

每条建议需保存：是否为目标 JD 明确要求、是否存在用户已确认差距、是否为后续能力前置、距计划投递还有多久，以及可展示的文字依据，以便解释“为什么排在前面”。优先级和差距状态分别记录；对尚未确认的能力不能伪造已确认缺口。

## 信息不足与初步诊断

若缺失信息显著影响 Top 3，最多优先提出 3 个补充问题。用户可选择“补充信息后再分析”或“先查看初步诊断”。后者记为 `preliminary` diagnosis：仍有关键未确认信息，建议顺序可能随补充而变化。本轮只在类型和 Mock 数据中支持，不实现完整页面。

## 林浩各阶段 Mock 状态

以下所有状态均为虚构测试案例，仅用于产品演示。

### A. 首次输入

林浩明确提供姓名、年级、专业、Java 后端开发实习目标、4 个月后投递、每周约 20 小时、学过 Java 基础，以及做过 Java + MySQL 学生管理系统。演示用模拟目标 JD 包含七项核心要求：

1. 熟悉 Java 基础、集合、多线程。
2. 熟悉 Spring Boot、MyBatis。
3. 掌握 MySQL，了解索引、事务。
4. 了解 Redis。
5. 熟悉 Git、Linux 常用命令。
6. 具备基本数据结构与算法能力。
7. 有完整后端项目经历者优先。

### B. 第一次 AI 理解

- `confirmed`：大三上学期、软件工程、目标 Java 后端实习、4 个月后投递、每周约 20 小时、学过 Java 基础、做过 Java + MySQL 项目。
- `inferred`：可能已具备进入 Spring Boot 学习阶段的基础。这是由模糊信息引发的偏乐观推测，不是已确认事实。
- `unknown`：Java 多线程掌握情况、MySQL 掌握深度、Git / Linux 使用情况。

### 第一次诊断

在尚未纠正推测时，模拟 AI 将 Spring Boot、完善 Java 后端项目、基础算法练习排在前三。多线程和 MySQL 深度等关键信息仍缺失，因此这是可被用户选择查看的初步诊断，建议可能变化。

### C. 用户纠正

林浩明确补充：Java 实际刚学完集合、多线程尚未学习、MySQL 目前只会 CRUD、学生管理系统只是 JDBC 课程作业。这些记录来源为 `user_correction`，覆盖冲突的“已具备学习 Spring Boot 基础”推测；旧推测仍可通过 ID 关联查阅。

### D. 修正后的诊断

1. **Java 核心基础 / P0**：JD 明确要求 Java 核心能力；用户确认多线程尚未学习；Java 基础是后续框架学习的重要前置。
2. **MySQL 基础 / P0**：JD 要求 MySQL、索引、事务；用户确认目前只会 CRUD。
3. **Spring Boot / P1**：是目标岗位关键能力，但当前排在 Java 核心基础和 MySQL 基础之后。Spring Boot 的个人掌握情况仍需确认。

数据同时保留两次诊断、纠正记录及建议变化关系，以支持后续回答“为什么建议发生变化”。后续用户选择 7 天行动、完成后反馈及重新调整建议仍属于产品闭环描述，本轮不实现该业务流程。

## 第二阶段范围

本轮仅固化上述规则、TypeScript 类型和林浩各阶段 Mock 数据；页面保持基础导航与占位状态，不实现完整业务流程。
