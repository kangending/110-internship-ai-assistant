# 页面与状态清单｜最终版

> 项目：110线上考试——面向首次准备实习大学生的 AI 求职准备助手  
> 产品形态：Desktop Web  
> 主要演示尺寸：1440 × 900  
> 主要使用角色：首次准备实习、已有明确目标岗位的大学生  
> 演示案例：林浩（虚构模拟案例）  
> 说明：本清单仅记录当前已纳入并已实现的页面、关键状态、抽屉、弹窗与受控 Mock 状态；不把未开发功能写入交付范围。

---

## 1. 编号规则

- `P01～P08`：8 个核心页面。
- `A/B/C...`：同一页面的关键状态或关键画面。
- `D`：Drawer / 抽屉。
- `M`：Modal / Dialog / 弹窗。
- `S`：跨页面的全局状态或受控 Mock 状态。
- “对应原型位置”统一使用最终截图目录中的建议文件名；截图完成后应保持文件名与本清单一致。

### P05 关键规则

#### 1. Executable Action

Java 核心基础为当前完整可执行演示方案，包含：

- Java 多线程基础；
- MySQL 索引基础；
- 基础算法。

每项必须展示：

- 目标；
- 完成标准。

只有具备可验证 `actionItems + completionCriteria + feedback mapping` 的方案才可创建 `currentAction`。

#### 2. Direction

Spring Boot、完善 Java 后端项目、基础算法练习等当前未配置完整可验证行动方案的方向，进入统一的 Direction 完成态：

- 明确“本次诊断已经完成”；
- 展示当前方向与真实优先级；
- 不伪造行动任务；
- 不直接开始行动周期；
- 提供“查看本次诊断结果”；
- 提供“体验完整模拟闭环”。

#### 3. 标准模拟闭环

点击“体验完整模拟闭环”后：

- 先弹确认 Dialog；
- 确认后载入“林浩·基础阶段”标准演示路径；
- 进入 P02 已预填状态；
- 后续 P03/P04 使用预设引导保证评审能够顺利体验 Java 可执行行动闭环。

#### 4. 返回

P05 → P04。

### S02 AI 失败规则

AI 失败不是通过垃圾输入或随机概率触发，而是受控 Mock：

- 明确告诉用户本次生成失败；
- 保留全部已填写信息；
- 提供“重新生成”；
- 提供“返回修改信息”；
- 不伪造正常诊断结果。

---

# 12. 演示模式可见入口说明

最终演示模式用于评审快速检查固定状态，不属于正常用户主流程。

当前应包含的受控演示入口，以最终 Web 原型实际文案为准，核心包括：

- 首次使用；
- 已有记录；
- 信息不足；
- 模拟 AI 生成失败；
- 模拟初步诊断（林浩）；
- 模拟用户纠正后（林浩）；
- 模拟行动进行中（林浩）；
- 模拟行动反馈完成后（林浩）；
- 模拟最新诊断（林浩）。

此外：

- 当存在正在进行的 executable currentAction 时，可出现 **“快进到本周期结束”**；
- 该项是时间快进操作，不是业务 Snapshot；
- “仅方向周期结束（旧状态）”等内部兼容状态不在评审 UI 中展示。

所有固定林浩 Snapshot 必须原子切换整套相关数据，不能出现“顶部是自定义岗位、页面却显示林浩 Java 后端诊断”的混合状态。

# 15. 截图执行规则

1. 所有截图以最终 Web 原型为准，不为了凑清单临时制作不存在的画面。
2. 每张截图优先使用 1440 × 900 的主要演示尺寸。
3. Drawer / Dialog 打开时应保留足够背景上下文，让评审知道它属于哪个页面。
4. 长页面可以：
   - 截完整长图；
   - 或使用“页面全貌 + 关键区域单独截图”的方式。
5. 相同页面只有在状态真正改变用户判断、操作或后续流程时才增加状态截图。
6. Hover、普通按钮按下态、无业务意义的小视觉变化不单独截图。
7. AI 失败、信息不足、Direction 终态、完成弹窗等边界状态必须保留独立截图。
8. 所有模拟数据与受控失败状态应在演示说明中明确标注为 Mock / 模拟案例。
