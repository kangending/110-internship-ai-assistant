# 演示说明

> 项目：110线上考试——AI 求职准备助手  
> 产品形态：Desktop Web  
> 推荐演示案例：林浩（虚构模拟案例）  
> 主要演示尺寸：1440 × 900  
> 说明：本项目为前端 Web 演示原型，使用 Mock 数据与受控状态进行演示，不依赖评审持有候选人的私人账号、模型额度、API Key 或其他密钥。

---

## 1. 访问地址

### Docker 演示（推荐）

在项目根目录执行：

```bash
docker compose up --build
```

浏览器访问：

```text
http://localhost:8080
```

停止演示：

```bash
docker compose down
```

### 本地开发模式

需要 Node.js 20.19+ 或 22.12+，以及 npm。

```bash
npm ci
npm run dev
```

浏览器访问终端输出的本地地址，默认通常为：

```text
http://localhost:5173
```

## 3. 预置角色

当前产品仅包含一个主要业务角色：

**求职学生**

典型用户为第一次正式准备实习、已有明确目标岗位，但无法判断自己与岗位要求之间的实际差距，也不知道下一步应优先准备什么的大学生。

本次演示不包含企业招聘方、管理员、导师后台、登录注册或角色切换。

## 4. 支持的模拟案例

### 林浩标准案例

林浩为虚构模拟人物：

- 大三上学期；
- 软件工程专业；
- 第一次正式准备实习；
- 目标岗位：Java 后端开发实习生；
- 计划约 4 个月后开始投递；
- 每周约 20 小时用于准备；
- 已学习 Java 基础、面向对象、集合；
- MySQL 只会基础增删改查；
- Git 会基本 add / commit / push；
- 做过学校课程中的 Java + MySQL + JDBC 学生信息管理系统；
- 尚未系统掌握多线程、Spring Boot、MyBatis、Redis、MySQL 索引与事务、Linux 等内容。

标准演示中，AI 首次会对林浩的能力产生偏高理解，用户通过“不准确”和补充信息纠正后，正式诊断调整为：

1. Java 核心基础 P0；
2. MySQL 基础 P0；
3. Spring Boot P1。

## 5. 推荐完整演示流程

```text
P01 首页
→ P02 建立诊断
→ S01 AI 分析处理中
→ P03 AI 理解确认
→ 补充 / 确认 / 纠正
→ S03 纠正后重新分析
→ P04 我的诊断
→ P05 行动选择
→ P06 当前行动
→ 模拟周期结束
→ P07 行动反馈
→ S04 行动反馈更新中
→ P08 本次更新结果
→ 查看最新诊断 / 返回首页 / 继续规划
```

## 6. 标准演示步骤

### 6.1 首页与建立诊断

打开 `http://localhost:8080` 后进入首页。

从首次使用状态开始，进入“建立诊断”，可载入林浩模拟案例并提交。

提交后会进入 AI 分析处理中状态，随后进入 P03「AI 理解确认」。

### 6.2 AI 理解确认

P03 会区分：

- Confirmed：已确认事实；
- Inferred：AI 推测；
- Unknown：待确认信息。

标准演示建议对 AI 推测选择“不准确”，并使用补充信息入口确认林浩当前的实际基础。

核心规则：

> 未提及 ≠ 不会。

AI 推测不能直接当作用户事实。

### 6.3 查看正式诊断

纠正后重新分析，进入 P04「我的诊断」。

重点查看：

- Java 核心基础 P0；
- MySQL 基础 P0；
- Spring Boot P1；
- 建议依据；
- 纠错前后的建议变化 Diff。

### 6.4 选择行动

选择 Java 核心基础进入 P05。

标准案例已为该方向配置完整可执行行动，主要包括：

- Java 多线程基础；
- MySQL 索引基础；
- 5 道基础算法题。

确认后设为当前行动。

### 6.5 当前行动与时间快进

进入 P06 后可查看：

- 周期目标；
- 行动内容；
- 完成标准；
- 行动依据；
- 当前“进行中”状态。

真实 7 天无法在评审期间等待，因此页面提供演示提示。

操作：

**左下角「演示模式」 → 「快进到本周期结束」**

该操作只模拟时间流逝，不会自动提交反馈，也不会自动把能力改成“已掌握”。

### 6.6 行动反馈

周期结束后进入 P07。

标准案例反馈为：

- 多线程基础已学习并写过 Thread / Runnable 示例，但仍不熟；
- MySQL 索引学习了一部分，但理解不深；
- 完成 5 道算法题，其中 3 道独立完成。

提交后进入行动反馈更新处理中状态。

### 6.7 更新结果

进入 P08 后重点查看：

- 新增的用户事实；
- Java 核心基础：`gap → partial`；
- MySQL：仍为 `partial`，但增加索引学习事实；
- Spring Boot：成为下一阶段主线；
- 本轮闭环完成提示。

之后可以查看最新诊断、返回首页或继续规划下一阶段。

| Direction 诊断完成 | P04 → 选择当前只有方向、没有完整可验证行动任务的建议 |

## 8. 演示模式说明

左下角「演示模式」是本次原型提供给评审的状态检查入口。

用于快速查看或触发：

- 首次使用；
- 已有记录；
- 信息不足；
- 模拟 AI 生成失败；
- 初步诊断；
- 用户纠正后的诊断；
- 行动进行中；
- 行动反馈完成后的状态；
- 最新诊断；
- 可执行行动的周期时间推进。

演示模式不是正常用户业务功能，而是为了在不等待真实时间、不依赖随机错误、不连接真实 AI 服务的情况下，稳定展示已经实现的关键状态。

---

## 9. 恢复初始演示状态

如果演示已经进入诊断、行动或反馈阶段，需要重新从头开始：

1. 打开左下角「演示模式」；
2. 选择「首次使用」；
3. 系统切回首次使用快照；
4. 返回首页后重新开始演示。

该操作用于清理上一轮演示中的目标岗位、诊断、当前行动、反馈和最新结果，避免旧状态影响下一轮演示。

如果只需要重新体验林浩案例，也可以再次载入林浩模拟案例。

---

## 10. AI 生成失败演示

当前原型没有接入真实 AI API，因此 AI 失败采用受控 Mock。

进入方式：

**左下角「演示模式」 → 「模拟 AI 生成失败」**

失败状态会：

- 明确提示本次分析没有生成成功；
- 保留已经填写的信息；
- 提供「重新生成」；
- 提供「返回修改信息」；
- 不伪造正常诊断结果。

## 11. Mock 与真实能力边界

以下内容为本次原型的预设 / Mock：

- 林浩个人背景；
- Java 后端目标 JD；
- AI 初始推测；
- 纠正后的诊断结果；
- Java 核心基础行动方案；
- 7 天后的行动反馈；
- 更新后的诊断；
- AI 失败状态；
- 时间快进。

这些状态用于验证产品流程、交互与业务规则，不作为真实用户研究结果或真实 AI 能力声明。

对于标准案例以外的输入，原型允许编辑并展示已实现的交互状态，但不会伪造当前 Mock 数据无法可靠支持的个性化建议。

## 14. 推荐评审顺序

如果时间有限，建议按以下顺序体验：

1. 首页载入林浩案例；
2. 查看 AI 理解确认；
3. 对 AI 推测执行“不准确”纠错；
4. 查看纠错后的正式诊断和 Diff；
5. 选择 Java 核心基础；
6. 设为当前行动；
7. 左下角「演示模式」→「快进到本周期结束」；
8. 提交行动反馈；
9. 查看 P08 更新结果；
10. 打开完成弹窗；
11. 最后通过演示模式查看「模拟 AI 生成失败」与信息不足状态。

该顺序可以在较短时间内覆盖：

**理解 → 纠错 → 诊断 → 行动 → 反馈 → 更新**

这一完整产品闭环。
